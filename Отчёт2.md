# Отчёт по развёртыванию Go URL Shortener в Kubernetes

## 1. Описание проекта

Приложение состоит из:

- Go-сервера, который предоставляет HTTP API;
- PostgreSQL, используемого для хранения сокращённых URL;
- механизма миграций базы данных;
- frontend-части приложения;
- Kubernetes-ресурсов для запуска и взаимодействия компонентов.

Все ресурсы приложения находятся в отдельном Kubernetes Namespace:

    url-shortener

---

## 2. Использованные абстракции Kubernetes

В проекте используются следующие основные Kubernetes-абстракции:

| Абстракция | Назначение |
|---|---|
| Namespace | Изоляция ресурсов приложения |
| Deployment | Управление Pod PostgreSQL |
| Pod | Запуск контейнеров приложения |
| Init Container | Выполнение миграций перед запуском сервера |
| Service ClusterIP | Доступ Go-приложения к PostgreSQL |
| Service NodePort | Доступ к Go-приложению извне Kubernetes |
| PersistentVolumeClaim | Хранение данных PostgreSQL |
| Secret | Хранение пароля PostgreSQL |


### 2.1. Namespace

Для изоляции ресурсов приложения создан Namespace:

    url-shortener
---

## 3. Deployment PostgreSQL

Для запуска PostgreSQL используется объект `Deployment`.

Конфигурация:

    kind: Deployment
    name: postgres
    replicas: 1

Deployment отвечает за поддержание одного экземпляра Pod PostgreSQL.

Внутри Pod запускается контейнер:

    postgres:18

PostgreSQL слушает порт:

    5432

В контейнер передаются параметры:

    POSTGRES_USER=postgres
    POSTGRES_DB=shortener

Пароль передаётся через Kubernetes Secret.

---

## 4. Pod PostgreSQL

Pod является минимальной единицей запуска контейнеров в Kubernetes.

Deployment PostgreSQL создаёт Pod, внутри которого находится контейнер
с PostgreSQL.

Упрощённая структура:

    Deployment postgres
            |
            v
        PostgreSQL Pod
            |
            v
      postgres:18 container
            |
            v
        port 5432

Kubernetes следит за состоянием Pod через Deployment и при необходимости
создаёт новый Pod.

---

## 5. PersistentVolumeClaim

Для хранения данных PostgreSQL используется:

    PersistentVolumeClaim
    name: postgres-pvc

Запрашивается:

    storage: 1Gi

и режим:

    ReadWriteOnce

PVC монтируется в контейнер PostgreSQL:

    /var/lib/postgresql

Это позволяет отделить жизненный цикл данных от жизненного цикла
контейнера PostgreSQL.

То есть данные базы находятся в Kubernetes storage, а не только внутри
файловой системы контейнера.

Схема:

    PostgreSQL container
            |
            | mount
            v
    /var/lib/postgresql
            |
            v
    PersistentVolumeClaim
            |
            v
       Kubernetes storage

---

## 6. Service PostgreSQL

Для доступа к PostgreSQL из других Pod создан Service:

    name: postgres
    type: ClusterIP

Service слушает:

    port: 5432

и перенаправляет трафик на Pod PostgreSQL:

    targetPort: 5432

Благодаря Service другие компоненты Kubernetes не должны знать
конкретный IP-адрес Pod.

Go-приложение подключается к базе данных по адресу:

    DB_HOST=postgres
    DB_PORT=5432

То есть используется DNS-имя Kubernetes Service.

Схема:

    Go Pod
       |
       | postgres:5432
       v
    Service postgres
       |
       v
    PostgreSQL Pod
       |
       v
    PostgreSQL :5432

---

## 7. Secret

Для хранения пароля PostgreSQL используется Kubernetes Secret:

    name: postgres-secret

Secret содержит:

    DB_PASSWORD

Приложение получает пароль через:

    valueFrom:
      secretKeyRef:
        name: postgres-secret
        key: DB_PASSWORD

Таким образом, пароль не записывается непосредственно в Deployment
приложения.

Secret используется как PostgreSQL, так и Go-приложением.

---

## 8. Deployment Go-приложения

Для запуска Go-сервера используется:

    kind: Deployment
    name: url-shortener
    replicas: 2

Deployment поддерживает два экземпляра приложения.

В результате создаются два Pod:

    url-shortener Pod 1
    url-shortener Pod 2

Каждый Pod содержит контейнер:

    urlshortener-server:latest

Контейнер запускает:

    ./server

Сервер слушает порт:

    8080

Схема:

    Deployment url-shortener
            |
            +-------------------+
            |                   |
            v                   v
       Go Pod 1              Go Pod 2
            |                   |
            v                   v
       ./server              ./server
            |                   |
            +---------+---------+
                      |
                      v
                  port 8080

---

## 9. Init Container для миграций

Перед запуском основного Go-сервера в каждом Pod запускается
`initContainer`.

Он выполняет:

    ./migrate

Используется тот же Docker image:

    urlshortener-server:latest

поскольку внутри image находятся оба бинарника:

    server
    migrate

Последовательность запуска Pod:

    Pod создаётся
         |
         v
    initContainer
         |
         v
    ./migrate
         |
         v
    миграции выполнены успешно
         |
         v
    initContainer завершается
         |
         v
    запускается основной container
         |
         v
    ./server

Основной контейнер не запускается до успешного завершения
initContainer.

Это обеспечивает выполнение миграций перед запуском приложения.

---

## 10. Миграции базы данных

Миграции выполняются программой:

    ./migrate

Она подключается к PostgreSQL через Kubernetes Service:

    DB_HOST=postgres
    DB_PORT=5432

При первом запуске выполняются необходимые SQL-миграции.

При последующих запусках Goose определяет текущую версию базы данных
и не выполняет уже применённые миграции.

Например:

    goose: no migrations to run. current version: 2

означает, что база данных уже находится на последней доступной версии.

---

## 11. Job для миграций

В конфигурации также присутствует Kubernetes `Job`:

    kind: Job
    name: migrate

Job предназначен для одноразового выполнения команды:

    ./migrate

Контейнер Job использует:

    urlshortener-server:latest

и подключается к PostgreSQL через Service:

    postgres:5432

Однако в текущей архитектуре миграции уже выполняются через
`initContainer` Go-приложения.

Поэтому Job и initContainer выполняют одну и ту же задачу.

Для итоговой конфигурации рекомендуется использовать один из подходов.

В данном проекте используется подход с `initContainer`, поэтому
отдельный Job для миграций не является необходимым.

---

## 12. Service Go-приложения

Для доступа к Go-приложению создан Service:

    name: url-shortener
    type: NodePort

Service слушает:

    port: 8080

и перенаправляет запросы на:

    targetPort: 8080

Service выбирает Pod по label:

    app: service

То есть запросы направляются на Pod, созданные Deployment
`url-shortener`.

Схема:

    Client
       |
       v
    Service url-shortener
       |
       +----------------+
       |                |
       v                v
    Go Pod 1          Go Pod 2
       |                |
       v                v
    :8080              :8080

Kubernetes Service обеспечивает распределение запросов между
доступными Pod приложения.

---

## 13. NodePort

Service Go-приложения имеет тип:

    NodePort

Это позволяет предоставить Kubernetes Service за пределами
ClusterIP.

В Minikube Service можно открыть командой:

    minikube service url-shortener -n url-shortener

Для локальной разработки также можно использовать:

    kubectl port-forward service/url-shortener 8080:8080 -n url-shortener

После этого приложение доступно по адресу:

    http://localhost:8080

# 14. Взаимодействие сервисов приложения

Основные компоненты взаимодействуют следующим образом:

    Client
       |
       | HTTP
       v
    Service url-shortener :8080
       |
       v
    Go application Pods
       |
       | PostgreSQL protocol
       | postgres:5432
       v
    Service postgres :5432
       |
       v
    PostgreSQL Pod
       |
       v
    PersistentVolumeClaim

Go-приложение не обращается напрямую к IP PostgreSQL Pod.

Вместо этого используется Kubernetes Service:

    postgres

Kubernetes DNS разрешает это имя в адрес Service.

---

## 15. Взаимодействие при запуске приложения

При создании Go Pod сначала запускается initContainer:

    ./migrate

Он подключается к:

    postgres:5432

и проверяет состояние миграций.

После успешного завершения миграций запускается:

    ./server

Основной сервер также подключается к:

    postgres:5432

и использует PostgreSQL для работы с данными сокращённых URL.

Таким образом:

    initContainer
         |
         | migration
         v
    PostgreSQL
         ^
         |
         | application queries
         |
    Go server

---

## 16. Использование конфигурации через Environment Variables

Конфигурация Go-приложения передаётся через переменные окружения:

    APP_PORT
    SHORT_LENGTH
    DB_HOST
    DB_PORT
    DB_USER
    DB_PASSWORD
    DB_NAME
    DB_SSLMODE
    CLEANUP_SECONDS

Основные параметры базы данных:

    DB_HOST=postgres
    DB_PORT=5432
    DB_USER=postgres
    DB_NAME=shortener
    DB_SSLMODE=disable

Пароль:

    DB_PASSWORD

получается из Kubernetes Secret.

Это позволяет не изменять Docker image приложения при изменении
конфигурации Kubernetes.
