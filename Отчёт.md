## 1. Описание технологического стека

В проекте реализован сервис сокращения URL (URL Shortener).

Используемые технологии:

- **Go** — язык программирования, на котором реализовано приложение.
- **PostgreSQL** — реляционная база данных для хранения данных приложения.
- **Docker** — контейнеризация приложения.
- **Kubernetes (Minikube)** — оркестрация и запуск приложения в локальном кластере.
- **Helm** — установка и настройка VictoriaMetrics.
- **VictoriaMetrics Single** — сбор, хранение и запрос метрик приложения и базы данных.

Приложение развёрнуто в Kubernetes в пространстве имён `url-shortener`.
Для приложения настроен Deployment с двумя репликами.

## 2. Сбор и хранение метрик

Для мониторинга используется VictoriaMetrics Single, установленная
в Kubernetes с помощью Helm-чарта `victoria-metrics-single`.

VictoriaMetrics собирает метрики с помощью Kubernetes Service Discovery.
Для обнаружения Pod'ов используются аннотации Kubernetes:

- `prometheus.io/scrape: "true"` — разрешает сбор метрик с Pod'а.
- `prometheus.io/port` — указывает порт, на котором доступен endpoint метрик.
- `prometheus.io/path` — указывает путь к endpoint метрик.

Метрики приложения собираются по адресу `/metrics` на порту `8080`.
Метрики PostgreSQL собираются с порта `9187`.

Для проверки состояния целей сбора используется API VictoriaMetrics
`/api/v1/targets`. Все три цели сбора — две реплики приложения и PostgreSQL
exporter — имеют статус `up`.

## 3. Использованные экспортеры

### 3.1. Метрики Go-приложения

Для экспорта метрик используется библиотека Prometheus для Go:

`github.com/prometheus/client_golang/prometheus`

HTTP endpoint `/metrics` предоставляет метрики, зарегистрированные
в реестре приложения. Для обработки endpoint используется `promhttp`.

Приложение экспортирует метрики HTTP-запросов, работы с PostgreSQL
и бизнес-метрики сервиса.

### 3.2. PostgreSQL Exporter

Для сбора метрик PostgreSQL используется готовый экспортер:

`prometheuscommunity/postgres-exporter:v0.18.1`

Экспортер развёрнут в Kubernetes в пространстве имён `url-shortener`
отдельным Deployment `postgres-exporter`.

Экспортер подключается к базе данных PostgreSQL и предоставляет метрики
на порту `9187` по пути `/metrics`.

Для подключения используются параметры базы данных, а пароль передаётся
через Kubernetes Secret `postgres-secret`.

Работоспособность соединения проверяется метрикой `pg_up`.
Значение `pg_up = 1` подтверждает успешное подключение экспортера
к PostgreSQL.

## 4. Реализованные бизнес-метрики

В приложении реализованы четыре бизнес-метрики, предназначенные для
мониторинга создания коротких ссылок и выполнения перенаправлений.

### 4.1. ShortLinksCreated

- **Тип:** Counter.
- **Экспортируемое имя:** `short_links_created_total`.
- **Описание:** общее количество успешно созданных коротких ссылок.
- **Назначение:** позволяет отслеживать количество успешных операций
  создания коротких ссылок и оценивать активность использования сервиса.

### 4.2. ShortLinkCreateErrors

- **Тип:** Counter.
- **Экспортируемое имя:** `short_link_create_errors_total`.
- **Описание:** количество ошибок, возникающих при создании коротких ссылок.
- **Назначение:** позволяет контролировать сбои при создании ссылок
  и анализировать надёжность соответствующей операции.

### 4.3. ShortLinkNotFound

- **Тип:** Counter.
- **Экспортируемое имя:** `short_link_not_found_total`.
- **Описание:** количество обращений к коротким ссылкам, которые не найдены.
- **Назначение:** позволяет отслеживать неуспешные попытки перехода
  по ссылкам и оценивать частоту обращений к отсутствующим ресурсам.

### 4.4. ShortLinkRedirectDuration

- **Тип:** Histogram.
- **Экспортируемые серии:** `short_link_redirect_duration_seconds_bucket`,
  `short_link_redirect_duration_seconds_sum` и `short_link_redirect_duration_seconds_count`.
- **Описание:** распределение времени выполнения перенаправлений
  по коротким ссылкам.
- **Назначение:** позволяет анализировать производительность операции
  перенаправления, оценивать среднее время обработки и перцентили задержки,
  например P95 и P99.

Гистограмма позволяет анализировать не только общее количество операций,
но и распределение их длительности. Это помогает выявлять замедления
в работе сервиса.

Счётчики увеличиваются при наступлении соответствующих событий и позволяют
анализировать общее количество операций за период, например с помощью
функции `rate()` в запросах PromQL.

## 5. Проверка работоспособности

Работоспособность мониторинга проверена следующими способами:

1. Проверена доступность endpoint `/metrics` приложения.
2. Проверена доступность endpoint `/metrics` PostgreSQL exporter.
3. Проверено подключение экспортера к PostgreSQL с помощью метрики `pg_up`.
4. Проверена конфигурация сбора метрик в VictoriaMetrics.
5. Проверено обнаружение трёх Pod'ов через Kubernetes Service Discovery.
6. Подтверждён статус `up` для обеих реплик приложения и PostgreSQL exporter.

## 6. Заключение

В рамках работы настроен мониторинг сервиса сокращения URL с использованием
VictoriaMetrics Single.

Реализован экспорт метрик Go-приложения, настроен сбор метрик PostgreSQL
через готовый PostgreSQL Exporter, а обнаружение целей сбора настроено
с помощью Kubernetes Service Discovery и аннотаций `prometheus.io/*`.


Система позволяет собирать и хранить технические и бизнес-метрики,
которые могут использоваться для анализа работы приложения и выполнения
последующих заданий.
